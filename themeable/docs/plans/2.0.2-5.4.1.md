# RomM-Themeable 2.0.2-5.4.1 Development Plan

*Every failure on main says what broke*

Oct 28, 2026 · Stealthx3

On Oct 28 an unreleased upstream `master` was merged into `main` outside the adoption workflow. The next build failed at its unit tests, but nothing reported it beyond a red run. `main` was reset to 2.0.1-5.4.1 at the owner's request.

## Tasks

1. **One failure report.** A `report` job runs when any job of the `themeable` workflow fails on `main`. It reads each failed job's log, lists its failing tests and errors with repository paths (`scripts/failure-report.mjs`), and opens the issue "themeable: the main build is failing", or comments on it while it is open. The verify job no longer opens its own issue. If issues are disabled, the report stays in the run's summary and the job says why it couldn't file it.

## Repository settings for the owner

- Enable issues, so failure reports can be filed.
- Protect `main` and require the `themeable` checks, so nothing reaches it without them.

## Version

`themeable/package.json` becomes `2.0.2`.
