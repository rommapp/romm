# RomM-Themeable 2.0.3-5.4.1 Development Plan

*Fixes from the review of the upstream PR*

Oct 28, 2026 · Stealthx3

Two findings from the review of rommapp/romm#5308 apply to the fork as it is.

## Tasks

1. **Read-only tokens can't change themes.** Every Branding route that changes something (save, rescan, upload, rename, delete, restore) needs `platforms.write`, the scope RomM's own server-settings routes use, on top of the admin role. Reading Branding still needs only `roms.read`. RomM's permission system has no scope for themes, and adding one would change its scope lists and migrations, so the fork reuses this one.
2. **Unsaved choices survive pack actions.** Branding's theme choice and Random toggles take the server's values on the first load and after a successful save only (`useBrandingChoices`). An upload, rename, delete or rescan keeps them, unless the chosen pack was deleted, which falls back to RomM default.

## Version

`themeable/package.json` becomes `2.0.3`.
