# RomM-Themeable 2.0.0-5.4.1 Development Plan

*Adopting RomM 5.4.1*

Oct 23, 2026 · Stealthx3

RomM 5.4.1 was merged into `main` by the upstream release workflow. It only updates dependencies and tooling: Node 24.22, uv 0.13.4, pip 26.2.2 in the image, Pillow 13, aiohttp, certifi, Vite, Storybook and the Trunk linters. Nothing the module patches or overlays changed.

## Review

Every check passes against 5.4.1: unit tests, the upstream check, the frontend source check on the new frontend dependencies, the backend tests on the new Python dependencies with uv 0.13.4, black 26.10.1, isort and ruff 0.17.1 on the backend overlay, and the visual check. No module code needs to change.

## Tasks

1. **Version.** Adopting a RomM release raises the module's major version, so `themeable/package.json` becomes `2.0.0`. The upstream release workflow now raises it on the adoption branch, so the next adoption doesn't need a manual bump.
2. **Report wording.** The upstream check only asks for `npm run catalog` when it found problems.
3. **Workflow pins.** `docker/setup-qemu-action` is pinned to a commit like every other action, and the artifact actions use the patched releases upstream moved to.

## Not taken

- Pinning the Node image used to build the frontend. The floating `node:24-alpine` tag already resolves to Node 24.22, and a digest pin would need a manual update for each Node security release.
