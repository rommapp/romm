# RomM-Themeable 1.1.2-5.4.0 Development Plan

*Fixes from the code review of 1.1.1-5.4.0*

Oct 22, 2026 · Stealthx3

A bug-fix release on top of 1.1.1-5.4.0. It is built on `release/1.1.2-5.4.0`, presented as a whole for approval, and only then pushed and merged into `main`.

## Tasks

1. **Pack files can't run scripts.** Packs may only publish images, fonts and stylesheets. SVG files with scripts, event handlers, `javascript:` links or embedded documents are refused. nginx serves `/themes/` and themed SVG artwork with a sandboxing `Content-Security-Policy` and `nosniff`, so a file opened on its own can't run code on RomM's origin.
2. **Changes roll back.** If the pack change or the settings write fails after a compile, the previous build stays live and nothing in the themes folder or `themeable.json` changes.
3. **Failed uploads say so.** Branding treats an upload answered with `ok: false` as a refusal and shows its reason.
4. **Preview tabs show the previewed tab icons.** The loader tags favicon links in a preview tab with the theme, like artwork, without changing the cookie.
5. **Random's preview skips deleted packs.** A pack deleted while its artwork loads is never shown.
6. **Comment and shared-value rules.** Long docstrings in `lib/compile.mjs` and `lib/manage.mjs` are cut to the repository's length. The pack id rule has one home in `lib/client.mjs`; nginx builds its pattern from it and the backend reads it from the client values in the compiler's status instead of declaring its own.

## Not taken

- Running the module's checks on upstream's `master` and adding it to upstream's own build. This fork isn't contributed upstream, and `themeable/GUIDELINES.md` keeps the module in its own image built from `main`.
- Restoring upstream's development `docker-compose.yml`. The root compose file belongs to the module and shows how to run the fork's image. Upstream's development stack stays available in upstream's repository.

## Version

`themeable/package.json` becomes `1.1.2`.
