# RomM-Themeable 1.1.1-5.4.0 Development Plan

*Branding polish, themed placeholder covers and a livelier Cabinet*

Oct 22, 2026 · Stealthx3

A bug-fix release on top of 1.1.0-5.4.0, from the owner's hotfix list. It is built on `release/1.1.1-5.4.0`, presented as a whole for approval, and only then pushed and merged into `main`.

## Tasks

1. **Branding intro.** Replace the paragraph above the theme list with one that describes only what this version does, and link the "Creating a theme pack" guide on GitHub.
2. **Managing packs in Branding.** Rename and Delete in the web UI, with RomM default and Random never renamable or deletable. Toggles on the Random entry choose whether RomM default, the built-in themes and the accessibility themes are in Random's draw. Accessibility themes carry a colored **Accessibility** label in their row, like the **Built-in** label, set by a `tags` entry any pack can use. The layout is chosen by the owner from mockups before it is built.
3. **Themed placeholder covers.** Games without a cover show RomM's generated art in a fixed purple. A pack can now recolor that art, or replace it with its own artwork in a few variants per kind (missing and unmatched), picked per game so a library doesn't repeat one tile. Every built-in pack ships artwork, and each Branding row shows a still preview of one cover.
4. **Cabinet.** Livelier stars again, and an original arcade-style ship that crosses the starfield every few seconds, looping cleanly.
5. **Theme list order.** Random, RomM default, the accessibility themes, the other built-in themes, then packs in the themes folder.
6. **Guides.** The pack guide covers `.zip` packaging, tags and the Accessibility label, placeholder covers and everything else added in 1.1.0 and 1.1.1.

## How it is built

- RomM's cover art is changed only through anchored patches, like the Administration tab and the backend router: the placeholder reads CSS variables the compiled theme sets, and falls back to RomM's own art without them.
- `tags` is an optional list in `theme.json`; `accessibility` is the one tag Branding labels and Random's toggles group by. Built-in accessibility packs use it instead of a description prefix.
- Random's inclusion settings are saved in `themeable.json` beside the server theme and hidden built-ins, and published in the manifest so the loader draws from the same pool Branding shows.
- Version: `themeable/package.json` becomes `1.1.1`.
